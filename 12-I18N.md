# Comandos

## Traduzir o site para português (i18n)

Repare que, mesmo com a navbar e os textos que escrevemos em português, coisas como os nomes dos campos do formulário ("Name", "Description") e as mensagens de erro de validação ainda aparecem em inglês — elas vêm prontas do Rails. Vamos usar o i18n (internacionalização) para trocar isso por português, sem precisar reescrever nada nos formulários.

---

### Adicionar a gem rails-i18n
---
O Rails já vem preparado para traduzir textos, mas as traduções prontas (como as mensagens de erro de validação: "can't be blank", "is too short", etc) precisam ser instaladas à parte. A gem `rails-i18n` traz essas traduções para várias línguas, incluindo português do Brasil.

Abra o `Gemfile` e adicione a gem (fora de qualquer grupo, junto das outras gems principais):

```ruby
gem "rails-i18n"
```

```bash
bundle install
```

---

### Definir o português como idioma padrão
---
Abra `config/application.rb` e adicione a linha `config.i18n.default_locale` dentro da classe `Application`:

```ruby
module Loja
  class Application < Rails::Application
    config.load_defaults 8.1

    config.i18n.default_locale = :"pt-BR"

    # ...
  end
end
```

---

### Traduzir os nomes de Categoria e Produto
---
A gem `rails-i18n` traduz as mensagens genéricas do Rails, mas não conhece os nomes dos nossos models e campos — isso é só nosso, e precisamos ensinar ao Rails. Crie o arquivo `config/locales/pt-BR.yml`:

```yaml
pt-BR:
  activerecord:
    models:
      category: "Categoria"
      product: "Produto"
    attributes:
      category:
        name: "Nome"
      product:
        name: "Nome"
        description: "Descrição"
        category_id: "Categoria"

  categories:
    new: "Nova categoria"
    edit: "Editar categoria"
    show: "Visualizar categoria"
    back: "Voltar"

  products:
    new: "Novo produto"
    edit: "Editar produto"
    show: "Visualizar produto"
    back: "Voltar"

  helpers:
    submit:
      create: "Criar %{model}"
      update: "Atualizar %{model}"
```

Isso é o suficiente para o Rails passar a usar esses nomes automaticamente: os `form.label` dos formulários (que hoje mostram "Name", "Description") passam a mostrar "Nome", "Descrição", e as mensagens de erro de validação também usam esses nomes (por exemplo, "Nome não pode ficar em branco" em vez de "Name can't be blank").

O bloco `helpers.submit` é outra tradução automática: é a chave que o Rails usa como texto padrão do botão `form.submit` quando ele é chamado sem texto (como fizemos nos formulários de Categoria e Produto). O `%{model}` é trocado pelo nome do model — que já está traduzido lá em cima, em `activerecord.models` — então o botão passa a mostrar "Criar Categoria" ou "Atualizar Produto", dependendo da tela.

As chaves em `categories` e `products` (`new`, `edit`, `show`, `back`) ainda não são usadas em lugar nenhum — deixamos elas prontas aqui para usar como exemplo no próximo passo, quando formos trocar os textos fixos das views (como "New product", "Back to products") pela função `t()`.

---

Vamos ligar o servidor (se ele já não estiver rodando) e conferir o formulário e as mensagens de erro.

```bash
rails server
```

Agora, acesse `http://localhost:3000/products/new` e tente salvar o formulário vazio, para ver as mensagens de erro em português.

Pronto! Sem alterar nenhuma view, os nomes dos campos e as mensagens de erro já aparecem em português.
